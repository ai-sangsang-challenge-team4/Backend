# 위험 분석 가드레일·예외 처리 PR 전달 문서

## 1. 변경 목적

외부 AI 장애의 Rule-only 폴백과 백엔드 내부 안전 단계 실패를 분리한다. 내부 실패는 모두
fail-closed로 처리하되, 프론트가 실패 지점을 구분해 안내할 수 있도록 공통 오류 응답의 `code`를
네 가지로 제공한다. 이 변경에는 DB 스키마나 migration이 포함되지 않는다.

## 2. 처리 흐름과 실패 경계

```text
원문 마스킹
→ Rule·반복 문맥 분석
→ LLM 문맥 분석(무효 출력은 1회 재생성)
→ Rule·LLM 병합 및 서버 점수 계산
→ 분석·태그·감사 이벤트 저장
```

- 위험 분석·수정안 생성 외부 AI의 연결·timeout·429·5xx 또는 검증 후에도 무효인 출력:
  Rule 결과로 점수·등급을 계산해 HTTP 200 Rule-only 잠정 분석을 제공한다.
- 아래 네 내부 단계 실패: 분석과 제출을 중단하고 트랜잭션을 롤백한다. Rule-only로 전환하지 않는다.
- 마스킹 실패 시 Rule도 실행하지 않으며 원문을 외부 AI에 보내지 않는다.
- 실패 응답에는 성공 응답의 `analysisMode`, `manualReviewRequired`, `riskScore` 또는 별도
  `aiAnalysisStatus`가 포함되지 않는다. 프론트는 HTTP 상태만이 아니라 `code`를 기준으로 분기한다.

## 3. 프론트 오류 계약

| HTTP | `code` | 발생 단계 | 서버 동작 | 권장 화면 처리 |
|---:|---|---|---|---|
| 500 | `PRIVACY_MASKING_FAILED` | 원문·Rule 근거·과거 문맥의 개인정보 마스킹 | 분석/제출 중단, LLM 미호출, 롤백 | 개인정보 보호 처리 실패 안내와 재시도 제공. 분석 결과를 표시하지 않음 |
| 500 | `RISK_RULE_PROCESSING_FAILED` | Rule 탐지·근거 위치화·반복 문맥/임계값 처리 | 분석/제출 중단, 롤백 | 위험 규칙 분석 실패 안내와 재시도 제공. Rule-only 결과로 오인하지 않음 |
| 500 | `RISK_SCORE_CALCULATION_FAILED` | 태그 기준 조회·병합 결과 점수/등급 계산 | 분석/제출 중단, 롤백 | 위험도 계산 실패 안내와 재시도 제공. 이전 요청의 점수를 새 결과처럼 표시하지 않음 |
| 500 | `RISK_ANALYSIS_SAVE_FAILED` | 분석·태그·감사 이벤트 저장 또는 flush | 분석/제출 중단, 롤백 | 결과 저장 실패 안내와 재시도 제공. 제출 완료로 이동하지 않음 |

공통 응답 예시:

```json
{
  "code": "PRIVACY_MASKING_FAILED",
  "message": "개인정보 보호 처리에 실패하여 위험 분석을 완료하지 못했습니다.",
  "timestamp": "2026-11-11T10:30:00",
  "path": "/complaints/42/risk-analysis"
}
```

프론트 구현 원칙:

1. 사용자 문구는 서버의 `message`를 표시할 수 있지만, 화면 상태 분기는 안정된 `code`로 한다.
2. 네 코드에서는 성공 캐시를 이번 요청의 새 결과로 표시하지 않고 제출 성공 UI도 노출하지 않는다.
3. 재시도 시 동일 요청을 다시 호출한다. 실패 응답만으로 클라이언트가 제출 상태를 임의 변경하지 않는다.
4. 알 수 없는 500 코드는 기존 공통 서버 오류 화면으로 처리한다.

## 4. AI 팀 전달 사항

- 위험 분석 LLM에는 원문이 아니라 마스킹 본문, 마스킹된 Rule 근거와 제한된 마스킹 대화 이력만 전달한다.
- LLM 스키마·허용값·근거 검증 실패는 같은 마스킹 입력으로 한 번만 재생성한다.
- 재생성도 실패하면 LLM 태그를 버리고 Rule-only 잠정 분석을 저장한다. 이때 LLM 상태는
  `UNKNOWN`, confidence는 `null`이며 생성형 수정안은 만들지 않는다.
- 위험 분석은 성공했지만 수정안 생성 AI가 실패해도 검증 전 하이브리드 결과를 저장하지 않고
  Rule-only 결과와 빈 수정안으로 전환한다.
- 마스킹·Rule·서버 점수 계산·저장 실패는 AI 품질 저하가 아니라 내부 안전 경계 실패다.
  LLM 재시도나 Rule-only 폴백 대상으로 취급하지 않는다.
- 로그와 예외 응답에 원문, 마스킹 본문, AI 응답 본문 및 인증 정보를 남기지 않는다.

## 5. PR 검증 항목

- `GlobalExceptionHandler`가 네 예외 단계를 HTTP 500과 정확한 코드로 변환한다.
- 서비스 테스트가 마스킹·Rule·점수·저장 실패의 구분과 fail-closed를 검증한다.
- 컨트롤러 테스트가 프론트가 받는 공통 오류 JSON의 `code`, `message`, `path`, `timestamp`를 검증한다.
- 외부 AI 장애의 Rule-only 200 경로와 내부 오류 500 경로가 서로 섞이지 않는다.
- DB migration은 보류하며 코드·API 계약·테스트만 변경한다.

### CodeRabbit 후속 반영

- 음수·역전·본문 범위 밖 LLM 근거 좌표를 substring 호출 전에 검증해 무효 AI 응답으로 처리한다.
  동일 입력으로 한 번 재생성한 뒤에도 무효면 Rule-only로 전환한다.
- 기존 Rule-only 분석 재사용은 `REUSED_RULE_ONLY`로 반환해 하이브리드 `REUSED`와 구분한다.
- 수정안 생성 AI 장애·무효 출력은 저장 전에 포착하며, 하이브리드 결과 대신 수정안 없는
  Rule-only 결과 한 건만 저장한다.
- 수정안의 미지원 태그 코드는 일반 런타임 오류가 아니라 `AiResponseInvalidException`으로 분류한다.
- Emergency 하향 승인 API 예시는 실제 정책대로 승인 즉시 `safetyLock=false`가 되도록 정정했다.

## 6. 보류·비범위

- 마스킹 실패 시 마스킹과 무관한 Rule 분석 결과라도 제공할지는 PM 결정 전까지 보류한다.
  현재 명세와 구현은 전체 분석/제출 중단이다.
- 실제 규정 RAG 답변 생성, High 제한형 템플릿 보완, Emergency 문맥 hard guardrail 정책은 이 PR 범위가 아니다.
- 운영 지표 저장 방식과 DB 기반 AI 실행 로그 스키마는 DB 연동 결정 후 별도 작업으로 다룬다.

검증: 서비스·예외 핸들러·컨트롤러 테스트로 네 코드와 fail-closed 동작을 확인한다.
